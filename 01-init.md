# /init — Project Initialization

> **Purpose**: Establish project identity, detect project type, and configure the workspace. This is the first command run on any new project.
> **Prerequisites**: None — this is always the starting point.
> **Output**: `docs/project-init.md`
> **Iterative**: No — run once per project.

---

## Instructions for the Agent

You are initializing a new software project. Your job is to ask targeted questions that establish the project's identity, type, and tooling so that all subsequent commands have the context they need.

**Behavior rules:**
1. Ask questions one group at a time. Wait for answers before proceeding.
2. Do not make assumptions about project type, tech stack, or scope. Ask explicitly.
3. After gathering answers, generate `docs/project-init.md` with all decisions documented.
4. Recommend the next command (`/requirements`).

---

## Phase 1 — Project Identity

Ask the developer:

1. **What is the project name?**
2. **Give a one-sentence description of what this project does.**
3. **Who is the intended user or audience?** (end users, developers, internal team, API consumers, etc.)

---

## Phase 2 — Project Type Detection

Ask the developer:

1. **What type of project is this?**
   - Full-stack web application
   - Frontend-only (SPA, static site)
   - Backend API / microservice
   - Mobile application (iOS, Android, cross-platform)
   - CLI tool
   - Library / SDK / package
   - Data pipeline / ETL
   - Desktop application
   - Other (describe)

2. **What is the primary tech stack?** (language, framework, database, hosting)
3. **Are there any hard constraints on technology choices?** (client mandates, legacy system integration, regulatory requirements)

---

## Phase 3 — Team & Process

Ask the developer:

1. **Is this a solo project or team-based?** If team-based, what roles are involved?
2. **Do you have existing mockups or wireframes?** (Google Stitch, Figma, sketches, etc.)
3. **Is there an existing codebase, or is this greenfield?**
4. **What source control and CI/CD setup do you use or plan to use?** (GitHub, GitLab, etc.)

---

## Post-Init

Tell the developer:
1. **File created**: `docs/project-init.md`
2. **Next command**: `/requirements` — to begin gathering detailed project requirements
3. **Reminder**: The workflow enforces a hard gate. No code will be generated until requirements, architecture, design, and integrations are all signed off.
